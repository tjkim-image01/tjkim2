## 2. 데이터 동작 흐름 (문의 접수 → 어드민 확인 → 판매 완료 및 재고 차감)

```
[1단계: 고객 문의 접수]
고객이 삐라상점(tjsites/site001-bira)에서 물건을 골라 [문의 접수] 클릭
   ↓
구글 엑셀(tjkim-items) 하단의 『삐라상점_문의』 시트 탭에 새로운 줄(Row)로 자동 등록!
(문의번호, 접수일시, 고객명, 연락처, 품목코드, 합계금액, 메모, 처리상태='접수')

[2단계: 어드민에서 확인 및 상담]

   ↓
『삐라상점_문의』 시트에 쌓인 문의 내역이 화면에 그대로 보임
   ↓

[3단계: 판매 완료 및 재고 숫자 자동 차감]
거래가 성사되어 관리자가 문의 상태를 『거래완료 (재고차감)』으로 변경

   ↓

   ↓

```

### Q1. 고객용 웹사이트(`tjsites`)에서 어드민(`tjkim2`) 주소를 추측할 수 없나요?
- **네, 추측할 수 없습니다.**
  1. 고객용 쇼핑몰 주소는 `.../tjsites/site001-bira/`이고, 어드민 주소는 전혀 다른 저장소인 `.../tjkim2/`입니다.
  2. 고객용 쇼핑몰 소스 코드(`tjsites` 저장소) 안에는 `tjkim2`라는 단어나 어드민 링크가 단 한 줄도 들어있지 않으며, `/#/admin` 페이지 코드 자체를 아예 삭제했습니다.

### Q2. 구글 엑셀은 승인된 사용자 아니면 못 들어가는데, 어떻게 웹사이트가 엑셀을 고치나요? 웹사이트가 비밀키(Key)를 가지고 있나요?
- **아니요! 웹사이트(브라우저)는 구글 엑셀의 비밀키(Key)나 비밀번호를 단 1글자도 가지고 있지 않습니다.**
- 만약 웹사이트 코드 안에 구글 마스터 키가 들어있다면 말씀하신 대로 해커가 웹사이트 코드를 뜯어보고 키를 훔쳐서 엑셀을 다 지워버릴 수 있습니다. **그래서 절대 그렇게 만들지 않았습니다.**

#### 💡 이해하기 쉬운 비유: **"은행 금고"와 "은행 창구 직원"**
1. **구글 엑셀 시트(`tjkim-items`) = 은행 지하 금고**
   - 이 금고는 오직 사장님의 구글 계정(`tjkim.image01`)만 열 수 있도록 잠겨 있습니다. 외부인은 절대 못 들어갑니다.
2. **Google Apps Script(`Code.js`) = 구글 은행 안에서만 일하는 '창구 직원'**
   - 사장님이 구글 시트 안(`확장 프로그램 → Apps Script`)에 직접 고용해 둔 **창구 직원 프로그램**입니다.
   - 이 창구 직원은 구글 서버 내부에 있기 때문에 금고를 열 수 있지만, **오직 사장님이 적어둔 업무 매뉴얼(`Code.js`)대로만 움직입니다.**
3. **웹사이트가 가진 것 = 금고 열쇠(X)가 아니라 '창구 인터폰 번호(URL)'(O)**
   - 웹사이트에 들어있는 주소(`https://script.google.com/macros/s/.../exec`)는 금고 열쇠가 아니라, 창구 직원에게 말을 걸 수 있는 **인터폰 번호**일 뿐입니다.

### Q3. 그럼 해커가 그 인터폰 번호(`.../exec`)를 알아내서 "엑셀 데이터 다 지워!" 또는 "가격을 0원으로 바꿔!"라고 해킹 명령을 보내면 어떻게 되나요?
- **창구 직원(`Code.js`)이 신분증(관리자 로그인 토큰)을 검사해서 100% 거절합니다.**

창구 직원(`Code.js`)은 인터폰으로 들어오는 요청을 **두 종류**로 엄격히 구분합니다:

#### 1) 신분증(로그인 토큰)이 없는 일반 방문자 / 해커가 요청할 때
창구 직원은 신분증이 없는 사람에게는 **딱 2가지 심부름만** 허용하고, 나머지는 전부 문전박대합니다.

| 방문자/해커의 요청 | 창구 직원(`Code.js`)의 처리 결과 | 해킹 위험 여부 |
|---|---|---|
| **"지금 파는 삐라 재고랑 가격 알려줘 (`ppiraStock`)"** | 엑셀 전체(37개 컬럼)를 주는 게 아니라, **원가·보관위치·기관신청이력·내부메모는 싹 가리고** 오직 `[품번, 수량, 판매가, 등급, 판매상태]` 5가지만 복사해서 창구 밖으로 내어줍니다. | **안전** (기밀 컬럼 유출 불가능) |
| **"구매 문의 남길게 (`ppiraInquiry`)"** | 오직 `삐라상점_문의` 시트의 **맨 아랫줄에 새 줄 하나를 추가(`appendRow`)**하는 것만 해줍니다. 기존 문의를 읽거나 고치는 기능 자체가 없습니다. | **안전** (기존 시트 수정·열람 불가능) |
| **해커: "엑셀 가격을 1달러로 고쳐줘! (`updateCells`)"**<br>**해커: "엑셀 원본 전체 내놔! (`dataset`)"** | 창구 직원이 **`checkAuth()`(관리자 비밀번호 확인)**를 실행합니다.<br>관리자 로그인 토큰이 없으므로 즉시 **`"Error: 로그인이 필요합니다"`**를 뱉고 차단합니다! | **해킹 완벽 차단** (엑셀 1글자도 수정 불가) |

#### 2) 관리자가 어드민(`tjkim2`)에서 비밀번호를 치고 로그인했을 때
1. 관리자 비밀번호의 정답(암호화된 `SHA-256` 해시값)은 웹사이트가 아니라 **구글 서버 내부의 비밀 금고(`ScriptProperties`)**에만 들어 있습니다.
2. 관리자가 어드민 화면에서 비밀번호를 입력하면, 창구 직원이 구글 서버 안에서 정답과 비교한 뒤 맞을 때만 **임시 출입증(토큰)**을 발급합니다.
3. 이후 재고 차감(`QTY - 1`), 가격 수정, 문의함 조회를 할 때마다 창구 직원이 이 출입증을 매번 확인하고 엑셀을 고쳐줍니다.

### Q4. 그럼 도대체 어떻게 사이트에서 비공개 엑셀을 바꿀 수 있는 건가요? 그게 앱스 스크립트(Apps Script)인가요?

**네, 정확히 맞습니다! 그게 바로 구글 엑셀 안에 내장된 『Google Apps Script (구글 앱스 스크립트, [`Code.js`](file:///Users/jatu/app/tjkim2/proejct-web/tj001/site/apps-script/Code.js))』입니다.**

원리는 아주 간단합니다:

1. **웹사이트는 엑셀을 직접 건드리지 못합니다**
   - 웹사이트(`tjkim2`, `tjsites`)는 구글 바깥(GitHub)에 떠 있는 화면일 뿐이라, 비공개 구글 엑셀에 직접 손댈 권한이 아예 없습니다.
2. **구글 엑셀 내부에 심어둔 『앱스 스크립트(`Code.js`)』가 대신 고칩니다**
   - 사장님이 구글 엑셀 상단 메뉴 **[확장 프로그램 → Apps Script]**에 [`Code.js`](file:///Users/jatu/app/tjkim2/proejct-web/tj001/site/apps-script/Code.js)를 붙여넣고 **[웹 앱으로 배포]**할 때 아래 두 가지 설정을 합니다:
     - **실행 주체 (다음 사용자로 실행): `나 (tjkim.image01@gmail.com)`**
     - **접속 가능 대상: `모든 사용자`**
3. **실제 엑셀이 수정되는 순간의 3단계 동작**:
   ```
   ① [어드민 웹사이트]
      관리자가 수량을 1 → 0으로 클릭
      → 앱스 스크립트 주소(https://script.google.com/.../exec)로
        "내 로그인 출입증은 이거고, APAC190103002B 수량을 0으로 바꿔줘"라고 메시지 전송
            ↓
   ② [구글 앱스 스크립트 (Code.js — 구글 서버 내부)]
      메시지를 받아서 먼저 "관리자 로그인 출입증이 진짜인가?" 검사 (checkAuth)
      → 가짜거나 출입증이 없으면 여기서 즉시 차단!
      → 진짜 관리자 출입증이 맞으면 다음 단계로 진행
            ↓
   ③ [앱스 스크립트가 사장님 권한으로 엑셀 수정]
      앱스 스크립트는 사장님 계정('나') 권한으로 실행되도록 설정되어 있으므로,
      구글 드라이브 안에서 비공개 엑셀(tjkim-items)을 직접 열어
      해당 칸의 숫자를 0으로 고치고 저장(setValue)함!
   ```
- 즉, **웹사이트에 엑셀 열쇠를 넣어둔 것이 아니라, 구글 드라이브 안쪽에 사는 앱스 스크립트(대리인)에게 사장님이 "관리자 비밀번호 확인하고 대신 엑셀 고쳐줘"라고 위임해 둔 구조**입니다.
- 그래서 외부에서는 해킹으로 엑셀에 절대 들어갈 수 없고, 오직 앱스 스크립트(`Code.js`)가 허락한 작업만 안전하게 수행됩니다.

## 4. 한 줄 요약

1. **어드민 경로 은닉**: 고객용 웹(`tjsites/site001-bira`)과 어드민(`tjkim2`)은 아예 다른 리포지토리로 분리되어 있고 고객 웹에는 어드민 페이지가 없으므로 경로를 추측할 수 없습니다.
2. **해킹을 통한 엑셀 변조 불가**: 웹사이트에는 엑셀 접근 키(Key)가 없으며, 구글 서버의 창구 직원(`Apps Script`)이 관리자 비밀번호 없이는 **엑셀 수정(`updateCells`)과 원본 열람(`dataset`)을 서버 단계에서 원천 차단**합니다.
3. **업무 자동화**: 고객 문의는 `삐라상점_문의` 시트에 쌓이고 → 어드민(`tjkim2/#/ppira`)에서 보이며 → **`거래완료 (재고차감)`**으로 바꾸면 `PRINT` 시트의 재고(`QTY`)가 자동 차감되어 쇼핑몰에 품절로 반영됩니다.
